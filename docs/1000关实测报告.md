# Tomato Blast · 1000 关实测报告

测试时间：2026-10-22 · 测试方式：自动打关机器人（学 Angry Smash 的 Autoplay：打最高的物件，同一目标两发没进展就换目标），在 8 个无界面浏览器里并行，按真实物理逐关实打。每关开局时钟归零（摆锤 / 移动挡板 / 转桌的开局位置固定）。**注意：同一页面里重复打同一关结果一致，但重新打开页面后同一关的结果仍会有小幅波动**（实测第 20 关一次 18 发、一次 21 发），来源没查清，怀疑是物理引擎内部求解顺序。所以最终以"用真实炮弹数实际打通"为准。

## 结论

- **真实炮弹数验收（不用道具）：1000 / 1000 关清台。**
- **道具验收（每 3 发里 1 发轮流用三连发 / 火箭 / 大西瓜）：1000 / 1000 关清台**，共用了三连发 2660 次、火箭 2407 次、大西瓜 2042 次，无报错。
- 机器人最少用量中位数 20 发；用道具时中位数 20 发。
- 炮弹数 = 机器人最少用量 + 余量（普通 +5，前 30 关 +6，困难 +3，超难 +4，且至少多 12%）；因为上面说的波动，第一轮真实验收有 87 关差 1–7 个没清完，这些关再加 25%（至少 +3 发）后重测，其中 9 关又加了一轮，最终全部清台。炮弹数中位数 25 发（原作同区间中位数 22 发）。
- 机器人代表"瞄得很准、不会用道具"的玩家；真人瞄准更差，但有道具和续关。手感仍需真人试玩确认。

## 关卡怎么来的

- 每关的数字参数照拆包里原作同一关：物件数、炮弹数、桌型和尺寸、转桌转速、挡板、摆锤、堆叠高度、材质比例（`data/level_params.js`，只有数字，不含原作摆法）。
- 摆法由我们的生成器用外形模板现生成（金字塔 / 城堡 / 双塔 / 台阶 / 山谷 / 天际线，后排可加高像看台），按镜头限制最多 8 层、3 排、110 个物件。
- 机关：转桌（一律做成圆桌）、圆桌、弹跳柱、皮纳塔、摆锤（挂在物件堆前面，是会动的障碍）、固定挡板。

## 实测发现并修掉的问题

1. 圆桌四面都远，物件很难推下去（第一轮失败关 72% 是圆桌）→ 圆桌最多 6 列宽。
2. 固定挡板把后面的物件封死 → 挡板后面那几列最多 2 层高。
3. 摆锤挂得太低，开局自己把物件扫下桌 → 改挂在物件堆前方。
4. 摆锤 / 移动挡板 / 转桌用的是从开机起一直走的时钟，同一关每次开局不一样 → 每关开局时钟归零（之后仍有小幅波动，见结论）。
5. 无界面浏览器缓存了旧代码，校准跑的是旧版 → 每轮清空浏览器缓存。
6. 个别关机器人 45 发打不完 → 换随机种子重新生成（参数不变，只换外形和材质抽样），见 `levels.js` 的 RESEED。
